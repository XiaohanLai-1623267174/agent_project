# 初始化说明：从克隆到第一次问答

本仓库不含运行期数据（`app.db` / `.chroma_db/` / `uploads/` / `knowledge_markdown/`），也不含任何密钥。
下面每一步都写清「数据落在哪里」，方便随时重置。

## 0. 前置

- Python：开发与测试都在 **3.14.6** 上（未在其他版本上验证过）
- Node.js：开发环境实测 **v24.20.0**（前端用 Vite 8）
- 一个可用的模型额度：**embedding 必需**（检索离不开它），生成/清洗/元数据各角色按 `.env` 里配的 key 决定

## 1. 密钥

```bash
cp .env.example server/.env
```

`server/.env` 至少要填：

| 变量 | 用途 | 是否必需 |
|---|---|---|
| `QW_API_KEY` | 阿里云百炼：embedding（以及可选云端 rerank） | **必需**（换 embedding 模型等于全库作废，见下） |
| `MS_API_KEY` / `MS_API_KEY_2` | 魔搭：`classify` / `title` / `rewrite` / `answer` / `direct` / `clean` / `metadata` 七个角色 | 提问与入库都需要 |
| `SENSENOVA_API_KEY` | 备用 | 可选 |
| `JWT_SECRET` | 登录令牌签名；不设会用代码里的占位默认值 | 生产必需 |

`env_bootstrap.py` 是 `.env` 的唯一解析入口，它会加载**服务端代码目录**下的 `.env`。
需要额外位置时用 `DSH_ENV_FILES`（`os.pathsep` 分隔）显式覆盖，不要再去各脚本里写 `load_dotenv`。

## 2. 安装与启动

```bash
pip install -r requirements.txt
cd server
python -m uvicorn fastapi_lianxi:app --host 127.0.0.1 --port 8000
```

- **不要加 `--reload`**：本项目此前用它会引入难以归因的不一致。
- **必须在 `server/` 目录下启动**：模块之间是扁平 import，`python -m` 会把当前目录加入 `sys.path`。

首次启动即自动创建：

```
server/app.db          SQLite（表结构自建）
server/.chroma_db/     Chroma 向量库
```

`uploads/` 与 `knowledge_markdown/` 会在真正上传文件时按需创建。

## 3. 前端

```bash
cd frontend
npm install
npm run dev
```

★ **访问地址用 `http://localhost:5173/`**。Vite 监听的是 IPv6 的 `[::1]:5173`，
用 `http://127.0.0.1:5173/` 会连接失败 —— 这是 IPv4/IPv6 的区别，不是前端没起来。

后端地址默认 `http://127.0.0.1:8000`，可用 `frontend/.env.local` 里的 `VITE_API_BASE` 覆盖。

## 4. 本地重排（可选）

不装也能跑：把 `server/.env` 里的 `RERANK_BACKEND` 设为 `cloud`（走云端）或 `off`（关闭重排）。

要本地跑：

```bash
cd rerank
pip install -r requirements.txt          # torch 很重；CUDA 版本按自己的显卡选
# 方式一：把模型放到 rerank/models/bge-reranker-v2-m3
# 方式二：用 RERANK_MODEL_PATH 指向已有目录
python rerank_server.py                  # 默认 127.0.0.1:8090
```

verify：`curl http://127.0.0.1:8090/health`（服务端会用 `RERANK_LOCAL_URL` 找它）。

## 5. 第一次问答（含入库）

1. 打开 `http://localhost:5173/`，注册一个账号并登录。
2. 进入知识库上传页，上传你要问的制度文件（PDF）。
3. 上传会走入库管线：`PDF → Markdown → chunks JSON → 入 Chroma / SQLite`。
   这一步会调用模型（清洗、chunk 元数据），需要额度；失败时接口会返回错误，**不会静默成功**。
4. 回到聊天页提问。回答里的引用序号对应检索到的制度条款。
5. 想看系统有没有在降级：`GET /health/degradations`（需要登录令牌）。

## 6. 数据都在哪 / 怎么重置

| 路径 | 内容 |
|---|---|
| `server/app.db` | 用户、会话、消息、文档与 chunk 记录 |
| `server/.chroma_db/` | 向量索引 |
| `server/uploads/<user_id>/` | 上传的原始 PDF（同时是 Agent 入库工具的允许根目录） |
| `server/knowledge_markdown/` | 解析出的中间 Markdown / chunks 缓存 |

全量重置 = 停服后删掉上面四项再启动（表结构与向量库目录会自动重建）。

★ **不要更换 embedding 模型**：Chroma 不会报错，只会返回不相关的结果 —— 换模型必须整库重新嵌入。

## 7. 常见问题

| 现象 | 原因 |
|---|---|
| `127.0.0.1:5173` 连不上，`localhost:5173` 正常 | Vite 监听 IPv6 `[::1]`，见第 3 节 |
| 启动报 `ModuleNotFoundError: config` | 不在 `server/` 目录下启动 |
| 聊天正常，但上传文件必失败 | 入库两环（`clean` / `metadata`）的模型额度不可用；与聊天链路用的是不同角色 |
| 检索结果明显不相关 | 可能换了 embedding 模型而未重新入库；或需要装本地重排 |
| 联网搜索结果为空 | 无 key 的搜索结果页可能临时反爬（源无可用性保证），此时功能会降级而非报错 |
